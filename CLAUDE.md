# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

MMChat ("Mudmast Chat server", VB6 project `ChatServer`, author "Dirocus") is a Visual Basic 6 hub server for the **MudMaster chat protocol**, the peer-to-peer chat built into MUD clients. It was written ~1999–2015 for Medievia players. It is published as a historical artifact, so **don't "clean up", reformat or modernise the code** unless asked. Fixes, if wanted, go in clearly labelled new commits.

There are no tests, no linter and no CLI build script. Build in the **VB6 IDE**: open `mmchat.vbp`, then File > Make. You can also run `"C:\Program Files (x86)\Microsoft Visual Studio\VB98\VB6.EXE" /make mmchat.vbp /outdir <dir> /out build.log`.
- **Server:** has no OCX dependencies and compiles as-is.
- **Plugins:** most plugins use `MSWINSCK.OCX`, which must be registered. One command-line build of such a project failed with "Error accessing the system registry" and then succeeded on retry without changes, without admin rights.
- **Build path:** VB6 embeds the `.vbp` path in the binary, so build from a neutral folder.

**File handling:**
- `.gitattributes` stores everything as-is (`* -text`) because VB6 needs CRLF line endings. Keep CRLF when editing.
- Keep the `VERSION`/`Begin…End` form headers and `Attribute VB_*` lines intact.
- The VB6 IDE re-cases identifiers project-wide, so case-only diffs between versions are noise (`git diff -w --word-diff` or `diff -i`).

## Architecture

### Wire protocol (MudMaster chat)
**Handshake:** the client sends `CHAT:<name>\n<ip><port>` and the server replies `YES:<servername>\n`. zChat clients are rejected, which makes zMUD fall back to MudMaster mode.

**Framing:** after the handshake, each frame is `<cmd byte><payload><0xFF>`:
- `namechange=1`, `creq=2`, `textall=4`, `textper=5`, `chatg=6`, `chatmsg=7`, `ping=0x1A`, `pong=0x1B`, `peek=28`
- `0x13…0xFF`: client version

**Commands:** users send commands as personal chats (`/chat Server who`). The text between the first and last `'` of the `textper` payload is the command line.

### Connection state
State is kept in each socket's `.Tag`:
- `"connect"` → `Connect()`: ban check, `users\<name>.usr` lookup, `ipauth` pair match.
- `"need pw"` → `pwauth()`: 15 s window via the hidden `pending` list.
- `"auth"` → `process()`.

`users(Index)` is parallel to the `Winsock(Index)` control array. Index 0 is the listener, and is also used for the HTTP update check while `init = False`.

`Check1` is "require auth". The `auth` command clears it for about 2 minutes; Timer1 restores it.

### Commands
`proccmds` first checks the command against `commands()`, which `loadsettings` fills with each command's:
- name
- perm level from `[Perms]` in `MMChat.ini`
- `sparams`/`nparams` (1 = at least N params, 2 = exactly N)
- help text

It then dispatches through one big `Select Case`. `Case Else` falls through to the plugins.

**Adding a command:**
- Raise the `commands()` bound in `mmchat.bas`.
- Add its entry in `loadsettings`.
- Add a `[Perms]` key.
- Add a `Case` and `Help/<name>.txt`.

### Output and persistence
- **Output:** `chatper` (one user), `chatall` (everyone) and `cchatall` (the sender's channel); index 0 means "from server".
- **Flood control:** `gag()` with `gagi`/`gagp`/`gagt`.
- **ANSI:** `stripansi()` cleans input.
- **Persistence:** all config goes through `GetFromINI`/`AddToINI` (the Win32 private-profile API). `GetFromINI` **writes the default back** when a key is missing.

### Plugins
**Loading:** `FindPlugIns` scans `Plugins\*.dll` and calls `CreateObject("<dllname>.Plugin")`, running `regsvr32 /s` and retrying on failure. The class must be named `Plugin`.

**Interface** (late-bound; see `Plugins/template/Class1.cls`):
- `GetName()`
- `init(appPath)`
- `GetCommands()`: returns `",Cmd,<lvl>,"`. Only the first digit of a level is read.
- `main(cmdLine, othervars)`: `othervars` is `path=…,servername=…,username=…,ocn=…,perm=…,`.
- optional `Timer()`: polled every 100 ms by `Timer2`.

**Return values from `main`:** results are separated by `~`. The first character of each picks the delivery:
- `0`: sender
- `1`: all except sender
- `2`: channel except sender
- `3`: all
- `4`: channel
- `5name,msg` / `6ocn,msg`: one user

**Concurrency:** a global `procplugin` flag allows only one plugin call at a time.

## Gotchas

**Known bugs:**
- `pwauth` doesn't call `stripansi`, so clients that colour their chats (MUSHclient) can't log in with a password. See HISTORY.md.
- Any runtime error in a command handler goes to `errored` in `Winsock_onDataArrival` and disconnects the user.

**Code style:**
- There's no `Option Explicit`, so typos are silent Empty Variants (`flase`, `vbnullsting` work by accident).
- Busy-waits with `DoEvents` (`timeout`) are everywhere, so handlers re-enter.

**Other:**
- Timer1 parses `Mid(Time…)` for :00/:30 seconds, which depends on the locale time format.
- `Dim dauser As String * 14` in `proccmds` truncates names in `listusers` and `fjoin`.
- Self-update writes the downloaded exe with `Print #` (text mode). The original update host was replaced with `mmchat.example.org` on import (in the binaries too, at the same length), so update checks just fail. Don't restore the original hostname or the original company name; both were removed at the author's request.
